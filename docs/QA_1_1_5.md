# Проверка 1.1.5

## Причины и изменения

Последние 25 завершённых ответов до правки: медиана до вызова воспроизведения 2078 мс, распознавание 447 мс, ожидание конца фразы 313 мс, первый токен 657 мс, первое предложение 837 мс, первый синтез 516 мс. Ожидание LLM-lock в этих ответах отсутствовало. Это замеры приложения, не акустический замер первого слышимого звука.

Найденная лишняя работа: отбор памяти вызывал LLM даже для реплик, которые затем обязательно отбрасывались тем же локальным фильтром; свежая цитата канала вставлялась перед всей историей; чтение потока LLM приостанавливалось на синтез каждого предложения.

Исправлены именно эти пути. Параметры пользовательской модели, голоса и распознавания не подменяются. Реальная разница до/после в Discord требует нового разговора; тесты не выдаются за измерение этой разницы.

## Проверки

- HTTP-проверка: для неподходящих реплик нет запроса к Ollama; смешанный пакет передаёт только кандидатов и сохраняет исходные индексы/авторство.
- Проверка потока: второе предложение генерируется во время синтеза первого, без запуска настоящей модели. При ошибке TTS поток закрывается; отложенное воспроизведение не зависает на заполненных очередях.
- Изменение фоновой цитаты не меняет префикс истории; текущий вопрос остаётся последним, маркеры памяти и ограничения контекста сохраняются.
- Qt: старые отклонённые автозаписи скрыты по умолчанию, доступны для просмотра и удаления после включения переключателя, после скрытия не остаются выбранными. Ручные сведения видимы. Данные не удаляются.

Все тестовые реплики синтетические. Личные базы, контекст, настройки и токен не входят в дистрибутив.

Результат: 372 backend-теста и 64 Qt-теста прошли. Собран установщик 1.1.5; frozen EXE прошёл `--verify-runtime` в отдельном профиле (код 0). Просмотрены состояния памяти на 1040×720 и 1220×870, с включённым и выключенным просмотром старых автозаписей. Все хеши 145 файлов backend.zip совпали с манифестом и исходниками; фактический токен и личные ID отсутствуют.
